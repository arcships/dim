# 在两台电脑之间切换 Dim Alpha

提案 · [#2269](https://github.com/arcships/dim/issues/2269)

我在 MacBook 和办公室的台式机上都装了 Dim Alpha，把后者命名为「办公台式机」。坐在 MacBook 前，我想在台式机的代码库里跑测试。到了办公室，我也想接着处理 MacBook 上的对话。我在手边的电脑上运行 `dima`，选要用的电脑，再用熟悉的 TUI。两台电脑使用同一个安装包，可以同时供本机和远端终端使用。[Alpha 入口](../../../npm/README.alpha.md)

验收基准是在同一台目标机上，用相同版本、相同配置的 CLI 通过受保护的 POSIX socket 操作 App Server 的结果。包括 Session 和管理方法、插件新增的方法、错误、进度、通知及 UI 生命周期。用户可以在远程 TUI 做本机 TUI 可以做的事。[入口契约](../contracts/session-boundary.md#a3-entries-and-export) · [客户端协议](../clients.md#2-what-clients-share)

## 设计框架

| 边界 | 关键决定 | 跟踪 |
| --- | --- | --- |
| 共享端与网络连接 | 本机设置控制共享，发现后验证 Token，通过 rutis-network 承载 POSIX 协议及 TUI 回连 | [#2275](https://github.com/arcships/dim/issues/2275) |
| 终端选机与会话 | `/devices` 先选电脑，再接入活跃会话或从远端根目录选项目开工，输入框标明目标 | [#2276](https://github.com/arcships/dim/issues/2276) |
| 两端的文件与系统操作 | App Server 负责远端项目、执行和设置。手边的终端负责剪贴板、本机附件及导出位置 | [#2277](https://github.com/arcships/dim/issues/2277) |

### 连接拓扑图

MacBook A 可以照常通过自己的 `daemon.sock` 使用本机 App Server。下图是从 A 的 `/devices` 选择办公台式机 B 时的网络路径。

```text
+-------------------+                          +----------------------------+
| MacBook A         |    局域网 / Tailscale    | 办公台式机 B               |
+-------------------+                          +----------------------------+
| /devices          |<.... 发现名称和地址 .....| 共享入口                   |
| 选中 B            |-------- 加密连接 ------->| 验证 B 的共享 Token        |
| dim-client        |<===== 双向 RPC 流 ======>| 共享进程 -> daemon.sock    |
| TUI leaf          |<------- UI 回连 ---------| 私有监听地址 <- App Server |
+-------------------+                          +----------------------------+
```

点线表示发现候选设备。也可以手输地址，从加密连接那一步开始。A 核对 B 的身份，B 验证共享 Token，同一条 rutis 链路随后承载独立的 RPC 流和 UI 回连流。UI 行的箭头表示 B 的 daemon 发起回连，建立后双向通信。换成从 B 操作 A 时，在 A 上开启共享并使用 A 的 Token 即可对调两端。切换到第三台电脑会建立该目标自己的连接。

### 模块架构图

```text
使用端 A / dima
  |-- /devices 或 --target  -> 选择目标，读取该目标的本机凭据
  |-- 会话选择器、输入框    -> 记录草稿及待回复项所属的目标和 Session
  |-- dim-client            -> 本机 daemon.sock 或所选目标的 RPC 流
  |-- TUI leaf              <- 接受目标 App Server 的 UI 回连
  `-- 本机 I/O              -> 剪贴板、附件选择、导出位置

共享端 B / 共享进程（由 B 的「设置 / 远程访问」控制）
  |-- rutis-network         -> 发现与链路管理
  |-- 共享 Token 验证       -> 允许已验证的链路打开流
  `-- terminalTransport（拟议）
        |-- RPC 流          -> B 的 daemon.sock -> App Server 分发
        `-- UI 回连流       <- B 的一次性私有监听地址 <- UiLeaf

共享端 B / App Server
  |-- 会话目录、Session     -> 查询活跃会话、接入原对话、执行任务
  |-- 工作区                -> 列出和校验远端目录（拟议）
  |-- 管理方法              -> 操作目标机的模型、MCP 和运行时设置
  `-- UiHost / UiLeaf       -> 注册终端，向本机私有监听地址发起回连
```

选中 B 后，终端通过 `dim-client` 查询 B 的会话和目录，并向选定的会话提交输入。B 的共享进程持有网络流与本机 socket，App Server 决定每个 RPC 的结果。连接中断后，A 保留目标和草稿，B 上已接受的任务继续执行。[原生客户端](../../../crates/dim-client/README.md) · [会话目录](../appserver/session-catalog.md#31-sessioncatalog) · [UI 注册与回连](../plugins/Tui.md#36-ui-registry-and-ui-leaves)

## 第一次从 MacBook 连接办公台式机

1. 在办公台式机上运行 `dima`。首页显示「当前电脑：办公台式机（本机）」和「切换电脑 /devices」。打开 `/settings → 远程访问`，开启「允许其他电脑连接本机」。共享默认关闭，「电脑名称」默认取这台电脑的系统主机名（hostname），例如 `office-pc`。可以在这里把 Dim 的显示名设为「办公台式机」，系统主机名和连接地址仍由操作系统和网络管理。Dim 记住这个开关，在入口就绪后公布实际可用的连接地址。关闭 TUI 后，只要办公台式机保持唤醒、共享打开且后台 Dim 正在运行，仍可连接。
2. 在 MacBook 上运行 `dima`。默认立即进入本机 Home，可以照常输入。打开「切换电脑」，已有的电脑先显示，发现结果陆续补入。扫描期间保留本机和手动添加入口。使用远端已有的模型，无需先给 MacBook 配一个 Provider。
3. 选中办公台式机，回车后输入办公台式机「设置 → 远程访问」页显示的 Token，也可以粘贴。「在 MacBook 上记住」默认勾选，验证成功后保存。验证通过后列出办公台式机的活跃会话，列表内也可以新建会话。进入会话后，屏幕显示当前电脑和目录，输入、审批、模型及 MCP 设置都作用于办公台式机。
4. 如果还想从办公台式机控制 MacBook，在 MacBook 的 `/settings → 远程访问` 开启「允许其他电脑连接本机」，然后在办公台式机输入 MacBook 自己的 Token。两端此后都能从自己的 `dima` 选择另一端。「远程访问」始终标明本机名。在 MacBook 上操作办公台式机会话时，该页管理 MacBook 的入站共享，模型和 MCP 等目标设置仍作用于办公台式机。

在办公台式机的「设置 → 远程访问」开启共享后，页面直接显示完整 Token，开始监听后显示可用地址。Token 独占一行，窄屏按实际字符换行，仍可逐字照录。以下地址和 Token 均为示例。

```text
|   [重置 Token...]                                  |

```

MacBook 上仍从普通输入框开始。在首页或对话中输入 `/devices` 打开选择器。

```text

```


`>` 表示键盘焦点，「当前」标记正在操作的电脑。办公台式机即使有两条路径也只占一行。选中「按地址添加」可使用共享方显示的任一地址。若只列出本机，显示提示「在另一台电脑的 /settings → 远程访问 中开启共享」。

### 第一次验证与重连

局域网公告和 Tailscale 发现只提供候选电脑及其地址。选择发现的电脑、输入地址或使用预设配置，都会进入同一条连接流程。在办公台式机上开启共享时，Dim 为该 Alpha 实例生成一个高熵随机共享 Token。用户可在办公台式机本机的「设置 → 远程访问」查看它。持有它的客户端获得该共享入口的完整 TUI/CLI 能力。

```text
+-- 连接 办公台式机 ---------------------------------+
| 共享 Token    [****************____]               |
| 请输入 办公台式机「设置 → 远程访问」显示的 Token。 |
|                                                    |
| [x] 在 MacBook 上记住                              |
|                                                    |
| Enter 验证并连接    Esc 取消                       |
+----------------------------------------------------+
```

每条新链路都由办公台式机验证 Token。验证成功前，客户端只看得到发现信息，无法访问会话、设置、业务连接或 UI 回连。首次使用时，用户输入的 Token 携带用于核对共享端的公钥指纹。客户端先在加密连接上验证对端持有对应私钥，再提交 Token 的秘密部分。凭据保存在本机凭据存储中，按已验证的实例身份查找。同名电脑、同一 IP 上的新实例都不能取得旧 Token。公告、地址、普通配置、命令行参数和日志均不携带秘密。

| 用户的操作 | 终端的行为 |
| --- | --- |
| 首次连接或未选择记住 | 弹出输入框，遮蔽输入。验证通过才可浏览该机的目录和会话。取消或输错时保留原会话，错误输入不会被保存。取消勾选仅在本次使用期间保留凭据。 |
| 已记住，断网恢复、重启 `dima` 或切换网络 | 再次连接同一实例时自动使用已保存的 Token。主动选电脑时显示它的活跃会话，当前会话断线后重连则回到原会话。超时或离线保留凭据和草稿。 |
| 办公台式机重置 Token | 办公台式机提示「所有已连接的远端都会断开」。确认后关闭这些链路及其业务流，旧 Token 即刻失效。下次连接提示「Token 已失效，请输入办公台式机设置中显示的新 Token」。已接受的任务继续运行。 |
| 关闭共享再开启 | 关闭时停止接入、断开现有远端并撤回公告。再次开启沿用原 Token，主动重置才会更换。 |
| 在 MacBook 忘记凭据 | 清除 MacBook 为办公台式机保存的 Token，下次连接重新输入。其他电脑保存的凭据继续有效。 |

办公台式机的共享 Token 可供多台客户端使用，重置会影响所有客户端。MacBook 共享自己的入口时使用另一份 Token。

## 找到电脑

| 我手头有什么 | 在「电脑」里怎么用 |
| --- | --- |
| 同一局域网的两台电脑 | 办公台式机开启共享后，MacBook 可通过局域网公告看到它。只展示提供 Dim 终端入口的电脑。网段隔离或组播不可用时，仍然可以输入地址。 |
| 已登录同一个 Tailscale 网络 | 支持发现时显示提供 Dim 的节点。也可直接输入办公台式机的 MagicDNS 名或 Tailscale IP，无需先把两台电脑接到同一 Wi-Fi。 |
| 固定地址或预先写好的配置 | 「按地址添加」接受主机名或 IP，可带端口。用户配置可预置同样的显示名和地址。手动和自动发现的条目进入同一张表，连接成功后记住该电脑。 |

列表按 Dim Alpha 实例身份归并。办公台式机同时出现在局域网和 Tailscale 时只占一行，可以有两条可用路径。显示名允许重复，初次连接时通过地址区分同名设备，身份确认后再归并。已保存但暂不可达的电脑标为「离线」或「连接失败」并提供重试。发现候选不等于已经连接。选中候选并验证成功后，显示目标电脑的活跃会话。

现有 Alpha 平台包提供原生 CLI 和 App Server。共享功能交付时，平台包还需包含所选链路的 rutis 宿主（Go 链路使用 Go 宿主）、发现及连接插件，并配置加载器，使普通安装完成后即可开启共享。打包和加载验证归入 #2275。[Alpha 安装说明](../../../npm/README.alpha.md) · [共享与传输 #2275](https://github.com/arcships/dim/issues/2275)

rutis-network 的 mDNS 文档列出了 macOS、Linux 的发布支持，其 TCP 示例监听回环。局域网版要在选定接口提供实际可达的 Dim 入口，入口就绪后再公告，Windows 的发布能力也要单独验证。现有 Tailscale 插件能按标签自动连接，也能按名称或 IP 直连，尚需将可用的 Dim 实例呈现给用户选择。个人 tailnet 无法使用标签发现时仍应支持手动名称或地址。两台真实电脑上的发现、共享启停和双向连接是交付条件。[mDNS 发现](https://github.com/arcships/rutis-network/blob/558af1888dff7012a295283d5a4a05d6b9d4da10/discovery/mdns/README.zh-CN.md) · [Tailscale 连接](https://github.com/arcships/rutis-network/blob/558af1888dff7012a295283d5a4a05d6b9d4da10/docs/design/04-link-tailscale.md)

## 选电脑，再选会话

在 `dima` 里打开 `/devices`，选办公台式机。首次输入 Token，之后使用已记住的凭据。每次主动选中远端，都打开这台电脑的会话列表。

```text
+-- 办公台式机 / 活跃会话 ---------------------------+
| > 修复导出超时      ~/Code/dim       运行中        |
|   整理首页文案      ~/Code/site      已连接        |
|                                                    |
|   + 新建会话...                                    |
+----------------------------------------------------+
```

沿用现有会话选择器的列表行、键盘操作和打开会话流程。一条可见会话只要有任一分支正在运行，或仍有客户端连接，就出现在列表里一次，跨工作目录展示。即使默认分支空闲、所有终端均已断开，另一条分支上的运行任务仍能从这里找到。按 Enter 接入原会话，直接使用它的工作目录。

现有 `SessionSummary.running` 表示默认分支的运行状态。#2276 需要目标 App Server 按会话汇总当前所有分支的运行状态，并结合 `attachedClients` 返回活跃列表。列举时只读取已有运行状态，避免为发现会话而恢复历史会话。[选机与会话 #2276](https://github.com/arcships/dim/issues/2276) · [会话目录](../appserver/session-catalog.md#31-sessioncatalog) · [会话选择器](../cli-commands.md#the-resume-picker)

选择「新建会话」打开远端目录选择器，从目标机的文件系统根目录开始。每次只列当前层的可见子目录，过滤点号开头和目标系统标记为隐藏的目录。列表为空时仍可选当前目录。下面是从 `/` 进入 `srv/` 后的画面。

```text
+-- 办公台式机 / 选择工作目录 -----------------------+
| 当前位置    /srv                                   |
|   ../                                              |
| > dim/                                             |
|   site/                                            |
|                                                    |
|   [在 /srv 新建会话]                               |
|   输入路径...                                      |
+----------------------------------------------------+
```

上下键选择，在子目录上按 Enter 进入，选 `../` 返回上一级。根目录省略 `../`。选择「在 /srv 新建会话」打开该目录的普通输入框，首次发送消息或 shell 命令时才创建会话。已经知道路径时，可选「输入路径」直接跳到对应目录。Esc 取消选目录并回到活跃会话列表。没有活跃会话时，列表焦点落在「新建会话」。[TUI Home](../plugins/Tui.md#36-ui-registry-and-ui-leaves)

远端工作区所有者在 #2277 提供创建会话前可用的逐层目录枚举与路径校验。每次读取所选目录的直接子目录，可见的 `target/`、`vendor/` 也能选择。目录无权访问或已移除时，在原位置提示原因。现有 `workspace.files.search` 使用文件补全索引，有独立的检索范围。[远端目录与校验 #2277](https://github.com/arcships/dim/issues/2277) · [相关的文件补全接口](../../../crates/dim-app-server/src/workspace_files.rs)

已知目的地时，`dima --target 办公台式机` 等同于在电脑列表选中它。`--cwd /srv/dim` 直接打开指定远端目录的空输入框，`--resume SESSION_ID` 直接恢复指定远端会话。

## 日常切换

滚屏和全屏共用「电脑」面板，可以从 Home 或会话中用键盘打开 `/devices`。提议在现有菜单的 `/web` 前增加这一项。`/connect` 继续用于 Provider，`/resume` 在当前电脑内选择会话。熟悉目标名后，可以直接用 `dima --target 办公台式机` 或 `dima --target 办公台式机 --cwd /srv/dim exec -p 'Run the tests'`。现有 `--server PATH` 保持原义。普通启动始终从手边的电脑进入，即使上次退出时看着办公台式机。[命令菜单](../cli-commands.md#command-menu)

客户端的 home 保存别名、连接配置引用、上次使用的远端工作目录和会话。改名保留电脑标识。草稿属于对应电脑和会话。切换只影响当前终端，一次性命令和另一个终端各用自己选择的电脑。

从办公台式机切回 MacBook，办公台式机正在跑的测试继续，MacBook 恢复它自己的草稿和对话。再选办公台式机并打开一条活跃会话时，拉取该会话的最新历史、审批和提问。如果它已休眠，显示「连不上办公台式机」，用户仍停留在 MacBook。使用办公台式机途中断线则保留办公台式机的名称和草稿，提供「重连办公台式机」和「返回本机」。此时暂停发送，不把下一条输入投给 MacBook。

### 输入框右下角的设备名

滚屏和全屏都在输入框底边右侧的项目路径前显示当前远端的设备名，格式为 `办公台式机:/srv/dim`。名字与 `/devices` 列表一致，默认是共享端的 hostname。本机会话只显示原有项目路径。切换目标成功时，名称和路径一起更新。路径较长时沿用现有路径缩写，有空间显示位置时优先保留设备名。

```text
+----------------------------------------------------+
| > 跑一下导出测试。                                 |
+---------------------------- 办公台式机:/srv/dim ---+
```

断线时目标仍是办公台式机，输入框保留草稿和目标位置，状态提示暂停发送。用户可以重连或返回本机。

```text
+----------------------------------------------------+
| > 再跑一次失败的用例。                             |
+-- 已断开，发送已暂停 ------ 办公台式机:/srv/dim ---+
  [重连办公台式机]    [返回本机]
```

从 `/devices` 选择远端时，客户端在候选连接上通过共享 Token 验证并完成 v4 `hello`。恢复会话时，在 attach 和首屏读取成功后交接输入。新建会话时，在远端确认路径并打开空输入框后交接输入。取消或失败保留原视图。交接时解除旧界面注册，迟到的通知和审批响应仍属于旧目标。提交后断线按原目标、Session 和提交标识核对结果，禁止自动重发。[Session 恢复](../clients.md#2-what-clients-share)

## POSIX 连接怎样跨机器

TCP 原型采用 rutis-network 已有的拨号和监听插件，把通过 mTLS 的通道交给 rutis。Tailscale 单节点链路可复用同一项终端连接操作。发布端运行在能够访问目标 POSIX socket 的账户下。每个目标的链路单独装配，因此候选 B 可以在 A 工作时完成握手，两台服务器导出的同名服务各在自己的宿主上下文中解析。[TCP 控制接口](https://github.com/arcships/rutis-network/blob/558af1888dff7012a295283d5a4a05d6b9d4da10/docs/design/06-link-tcp-integration.md)

**链路和 App Server 有两次不同的握手。** rutis 链路就绪并通过共享 Token 验证后，客户端为每条业务连接打开一条流，服务端为它连接配置好的 `daemon.sock`。客户端经这条流发送现有 NDJSON，包括第一条 v4 `hello`。回复、空闲时送达的通知和 EOF 经同一条流返回。附属查询可以打开自己的连接。每条连接独立关闭，支持背压。网络传输按有界数据块搬运，须承载 POSIX 能接收的最大合法帧及多帧连读。App Server 自己执行分发、生成请求结果和通知。[dim-client](../../../crates/dim-client/README.md) · [TCP 帧上限](https://github.com/arcships/rutis-network/blob/558af1888dff7012a295283d5a4a05d6b9d4da10/docs/design/06-link-tcp.md)

**服务面。** 拨号端使用链路行的本地控制服务，调用 `configure`、`start`、`status`、`waitForChange` 和 `stop`。目标侧的连接进程拥有 socket 和监听器。提议在该进程的独立 rutis 宿主中发布一个 `terminalTransport` 数据面，支持打开业务连接、准备并接受一次 UI 回连、按流标识读写字节块和关闭。UI 回连准备就绪后返回流标识和目标侧监听地址。EOF、链路失效或显式关闭要唤醒等待读写的任务，并释放所属资源。该面只搬运终端流量，业务方法仍由 App Server 的现有入口分发。[服务面约定](../service-faces.md) · [App Server 入口](../contracts/session-boundary.md#a3-entries-and-export)

**UI leaf 需要回程。** 首次 attach 时，使用端 A 先准备好本机 leaf 的监听，再向 B 的 `terminalTransport` 申请一次性监听，取得 B 上的私有地址和回连流标识。A 将 B 返回的地址作为 `ui.open` 的 `address`，将 A 的 leaf 标识作为 `peer`。B 的 daemon 拨该地址，B 的共享进程把这条连接交给已准备的回连流，A 将其接到本机 leaf，双方在 `ui.open` 返回前完成握手。TUI 所有者在 #2275 实现时将远端地址的选择写入 §3.6。握手、token、代际替换和 `ui.close` 沿用现有所有者。失败须清理两端的监听和连接。切换时只释放旧目标的 leaf，旧 leaf 的结束事件不能终止新目标的 TUI。[UI 注册与关闭](../plugins/Tui.md#36-ui-registry-and-ui-leaves)

## 同一个动作在哪一端生效

原生文件接收、远端 `@` 补全和显式 `--cwd` 的模块与线路提案见[远程会话的文件输入](native-session-file-input.md)。

| 操作 | 用户可见的结果 |
| --- | --- |
| 工作目录、`!`、工作树、仓库范围的 `/resume` 和工作区文件补全 | 目标机解析路径、探测 Git 根目录并执行。两端存在同名目录时，工作区文件来自目标机。 |
| 输入图片、剪贴板、附件、导出 | 终端选择的本机文件在本机读取并传内容，引用的远端工作区文件由目标读取。保存导出写入用户在终端指定的位置。需覆盖大文件及两端同名但内容不同的文件。[附件输入](../cli-attachment-input.md) |
| 模型、账号、MCP、服务端设置、插件、运行时 | 读写所选服务器。打开浏览器和接收本机登录回调仍在终端一侧，回调及凭据交换结果路由到发起登录的目标。 |
| `/web`、诊断、更新、daemon 管理 | 浏览器可以从用户机器打开所选服务器的 Web 工作区，包括只监听回环的部署。诊断标明来源。安装动作标明作用端，更新客户端和更新目标服务器分别在所属机器执行。显式停止只作用于指定 daemon。通过共享验证后协商协议，版本冲突显示在该目标上。 |

本地与远端路径不同，会影响当前 CLI 的参数解析、文件导入、后台查询以及依赖本机 home 的操作。实现要逐项确认现有命令在远端的结果，包括只在本机执行的命令。退出、重新进入 TUI 和后台任务重新建连都必须保留目标。[CLI 设计](../cli-commands.md) · [Web 工作区](../web-workspace.md)

## 交付验收

1. 用两个隔离 home 启动 A、B，与各自 POSIX 连接比较完整 `hello.features`、管理读写、Session 调用、错误与并发通知。插件热加载后仍由目标 App Server 决定方法集。覆盖大帧、独立连接关闭以及提交后断线。
2. 通过同一目标跑 line mode 和 `exec`，验证输出、退出码和脚本输入输出。用 tmux 在两种 TUI 中跑 `Local → A → B → A`，包括 A 有草稿、待批操作和运行中任务，B 连接失败、同名 Session 以及服务端关闭旧 UI 的情况。用两台机器上的同名路径核对输入框底边，成功切换时显示目标设备名，断线时保留该名称，回到本机时只显示本地路径。
3. 用无共享文件系统的两端验证目录、附件、导出、浏览器回调和 Web 访问。在 B 改一项设置后，从 A、B 的原生 CLI 分别读取，验证只改到了 B。逐项对照现有 CLI 菜单和命令，验证每个动作的实际结果。
4. 在两台只装了 Alpha 平台包的电脑上，验证安装包自带的宿主及插件能由加载器启动，并分别通过 `/settings → 远程访问` 开启本机共享，再从 A、B 的 `/devices` 完成一次对另一台的操作。在 A 控制 B 时关闭 A 的入站共享，验证 B 的共享状态和 A 到 B 的出站会话保持可用。先走同一局域网，再移到不同局域网走 Tailscale。验证自动发现、手动地址、双路径合并、退出共享方 TUI 后重连、关闭共享后的撤回，以及睡眠恢复。目标暂不可达时，本机仍可正常工作。
5. 在无剪贴板的窄终端上，从共享方设置页逐字读出完整 Token，在另一台电脑手动输入并连接。用首次发现和手动配置分别验证缺少或错误 Token 时无法打开任何业务流。记住后重启客户端、在局域网和 Tailscale 间切换，均可自动验证并恢复。重置 Token 时现存连接断开，旧 Token 被拒，同地址的替代实例无法收到保存的秘密。
6. 从普通 `dima` 经 `/devices` 选择 B。跨目录列出 B 上正在运行或有客户端连接的可见会话，覆盖只有非默认分支运行且没有客户端连接的会话、已连接的空闲会话及没有输入预览的活跃会话，排除只有历史的会话。选择一条直接进入原对话。活跃列表为空时仍能选「新建会话」，从 B 的根目录逐层进入一个仅 B 存在的空目录，选定后打开输入框。验证隐藏目录与普通文件不出现在列表，返回上级、手输路径、无效路径、取消以及断线后重连原会话的行为。首次提交前验证新建流程没有创建 Session。

现有 TUI 和 RPC 分发各保留一份实现，每台 App Server 独立拥有 Session 和存储。配对设备入口的设计由 [#1897](https://github.com/arcships/dim/issues/1897) 跟踪，跨机器放置业务插件由 [#1288](https://github.com/arcships/dim/issues/1288) 跟踪。
