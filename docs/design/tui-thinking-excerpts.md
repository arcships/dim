# TUI 思考摘录与正文收起

在现有一行思考展示上选择可读的原文单元，并让 fullscreen 已展开思考的正文支持延迟单击收起。
不新增模型调用、服务、Timeline 事件或持久化状态；scrollback 展开的完整流式正文不变。

范围来自 [#1658](https://github.com/arcships/dim/issues/1658)，验收记录归 issue／PR。
显示合同见 [transcript detail settings](cli-commands.md#transcript-detail-settings)，鼠标手势合同归
[CLI 鼠标交互](../../crates/dim-cli/README.md)；本文件说明选择机制、成本边界和验证方法。

## 范围与用户效果

覆盖 scrollback、fullscreen 主 transcript 和已有分支侧面板。摘录只使用 provider 已允许展示的思考原文，
保留原文语言，不翻译、不生成语义总结，也不恢复隐藏 reasoning。没有可见原文时只显示正在思考状态。
已完成行保留既有用时；工具或正文接手后，旧摘录只属于历史，不固定到活动状态位。
当前执行阶段与等待对象属于 [#1659](https://github.com/arcships/dim/issues/1659)，这里不新增第二份活动摘要。

以下是合成原文及拟议效果，不是终端实测截图：

```text
原文依次到来：
先确认缓存失效边界。
读取调用方后再决定是否修改。
还需要核对异步任务的

collapsed：
 ◆ Thinking excerpt · 读取调用方后再决定是否修改。

fullscreen expanded：
 ◆ Thinking…
 ▎ 先确认缓存失效边界。
 ▎ 读取调用方后再决定是否修改。
 ▎ 还需要核对异步任务的

settled collapsed：
 ◆ Thought for 18s · 读取调用方后再决定是否修改。
```

未完成尾句不替换上一完整句。新增完整句后才更新摘录；最后一行没有句末标点或换行时，不因结束就冒充完整句。
示意中的英文标签沿用 CLI 本地化机制，中文界面使用“思考摘录”“正在思考”等对应文案。

## 摘录选择与刷新

### 同一块使用同一个选择规则

1. 在既有客户端投影消费新文本的边界增量处理，不从 renderer 回读整个块。
   只保留最近完整单元和当前未完成单元的开头，各至多 1 KiB UTF-8 文本；不额外保存尾窗或第二份正文。
   新字符只更新当前单元；预算是显示计算限制，不截断保存的原文。
2. 按原文顺序寻找最近完成的单元：句末边界或非空硬换行。一个硬行内优先取最后一个完整句；
   比较候选的结束位置，取最新候选，不把更早的完整句置于更新的完整行之上。
   `。！？` 和英文 `!?` 可结束句子；英文句点只在后接空白、硬换行或块结束时确认为句末，
   连续句末标点和紧随的闭引号归入同一句。小数点及路径、URL 内部的句点不作为边界。
   这是可测试的原文切分启发式，不保证理解缩写或语义；不以 `…`、`...`、逗号或冒号认定完整句。
3. 没有新完成单元时保持已展示的完整摘录，即使后续未完成文本很长。
   初始尚无完整单元时，展示当前未完成单元的开头并加省略标记；持续无换行长文本保持这个开头，不滚动追逐尾字。
   首个片段随可用文本增长到显示预算，随后保持稳定，直到出现新完成单元。
4. 摘录必须来自同一原文单元，只可折叠展示空白、沿用既有显示清理和添加截断标记；
   不拼接不相邻句子。候选过长时保留其开头，按 terminal cells 和完整 grapheme 截断。
   已选片段供 resize 重画，超出部分明确省略，不为扩大终端重读全块。
5. 完成时立即处理最后的候选，保留上一完整摘录优先于未完成尾句。
   无完整单元时仍使用带省略标记的片段。历史载入在既有事件投影中使用同一增量规则，
   不另读历史、不为摘录再扫描重建后的整块正文；不声称恢复了现有历史窗口之外的原文。

有界片段不保证保留任意长句的全文。选择保留截断标记，而不是扩大缓存或制造语义总结。
已有显示源码持有完整正文不代表摘录代码可以每帧对其 `split`、`join`、复制或计数字符。

### 只合并摘录绘制，不延迟事件消费

运行中摘录内容最多每 500ms 发布一次；候选变化只标记本地待刷新，到期由已有事件循环绘制最新候选，
不逐个回放积压 delta。首个可见片段、块结束、进入工具／正文及切换视图立即反映状态；
resize 立即按新宽度重画已选片段，不绕过节流去扫描历史。
用时和已有动画保持各自节奏，不能让动画帧反复执行摘录选择。
只有 streaming 块保留绘制节流状态；块结束后直接使用投影的最终片段，不再保留第二份历史绘制缓存。

摘录缓存归客户端投影／展示更新路径所有，renderer 只接收已选片段和状态。
缓存键使用 Session、分支、请求和思考块身份；身份、offset 及用时语义遵循
[Clients 的块身份合同](clients.md#timeline-block-identity)，不增加另一种 durable 标识。
preview 转 durable 时按现有 provisional 关联转移缓存，不能重开摘录或重置手动展开选择。
durable 摘录解析状态随新 delta 前进；preview 从该小状态的副本处理已有 progress 尾部，
不推进 durable 状态。preview 被替换或撤销时重新派生，不保留未提交的候选；不重扫 durable 前缀。
中断后被投影丢弃的临时思考不能留在历史缓存中。

片段都是可丢弃的派生显示缓存，不是第二份全文或持久化摘要。保留块移出既有历史窗口时释放其绘制缓存，
不无限累计访问过的 Session／分支。回看历史按当前块重算，不恢复后台工作。
不改变 progress 的 offset 计量单位，不把 Unicode 字符 offset 直接用作 UTF-8 字节下标，
也不为选择片段遍历完整正文换算 offset。

安全清理必须先于候选判定与显示。复用现有终端控制字符清理；不能在任意原始字节处截窗再重置清理状态，
否则可能把 OSC 等控制序列内的隐藏文本当作摘录。复用现有清理器的状态转移，
保留跨 delta 的控制序列解析状态，不能每帧清理完整历史。
该小范围解析状态只服务既有清理规则，不是新的文本格式或语义分析器。

### 两种模式与窄屏

- Scrollback collapsed 仅替换当前 live row，结束只提交一次历史行；已输出历史不因摘录 timer 回写。
  expanded 继续向 native scrollback 输出完整正文，不加预览上限，不因切换详情或 preview 转 durable 重复提交。
- Fullscreen 主 transcript 和侧面板按各自可用宽度绘制自己的块，保留现有默认设置和手动选择。
  缓存不通过相同屏幕行号或 main 的最后摘录共享；同一块在不同宽度下只共享原文选择，不共享截断后的行。
- 优先保留状态词；空间不足时先省略摘录及分隔符，再缩短用时／标签，极窄时只保留能容纳的状态文字。
  复用现有 cell／grapheme 工具，最终行不超过可用列宽；中文、组合字符和 emoji 不按字节截断。

## Fullscreen 正文单击收起

只扩展已展开思考块的正文实际行、块内 gutter 和空白行；不包含块间分隔、页面空白、滚动条或 dock 的非思考区域。
标题仍按现有有效 press/release 即时切换。正文只执行“收起这个仍展开的块”，不执行盲目 toggle；
tool、hook、error、compaction 等其他块继续遵守原来的标题命中规则。

当前 live tail 的思考预览也按源块身份命中，手动选择随 preview→durable 转移。
侧面板其他行刷新不取消仍有效的多击或选区；只有所操作行的内容、身份或坐标映射失效才取消。

复用 fullscreen 的 press/release、文本选择、链接和现有 400ms 多击窗口。
renderer 的命中结果需要区分思考标题与正文，并提供当前文档身份到真实块身份的关联；
不能只删除 `App::click` 的全局 `row == 1` 限制，也不能让 `Document::disclosure` 把整块正文视作标题，
后者会改变 hover、press 和文本选择的既有语义。

| 输入或变化 | 待确认正文单击的处理 |
| --- | --- |
| 同一有效思考正文内同一 cell 的首次无拖动 press/release，且未命中链接 | 登记一个目标及截止时间；不立即收起 |
| 400ms 多击窗口结束，且按钮已释放 | 重新校验后仅收起一次，清空待确认状态 |
| 第二／第三次 press、拖动或选词／选行 | 先取消待确认收起，再按既有选择规则处理 |
| 链接 press/release | 走原有链接操作，不登记收起 |
| 滚动、滚动条操作、resize、覆盖面板打开、鼠标模式关闭、Esc | 取消待确认收起 |
| Session／分支／侧面板目标切换、块被替换／移除或手动收起 | 取消待确认收起 |

窗口以首次 press 的时间为基准，与现有多击判定一致；长按后释放时若窗口已结束，可在下一事件循环立即确认。
任何新 press 都先取消旧待确认项，包括另一块上的 press，不把它们排队。
第二／第三击的 release 不重新登记收起，即使点击 gutter 没有产生可复制的选区也一样。
在截止时间边界先处理已收到的输入，再确认到期项，避免已识别的双击仍触发第一次收起。

客户端事件循环最多保存一个待确认手势，包含视图世代、Session／分支／请求／真实块身份及截止时间，
不保存屏幕行号作为到期动作目标。到期时重新确认仍是同一视图、同一思考块且已展开，
没有选择、链接或其他更高优先级操作；否则直接丢弃。真实动作更新已有的逐块展开选择，沿用现有视口锚定。
同一规则用于主 transcript 和侧面板，展开选择仍各自独立。

待确认项由现有本地 tick／超时驱动，不 `sleep`，不启动后台任务，不发送 RPC；
普通输入、Stop、模型和工具事件继续消费。不能借用会执行状态查询的业务轮询来实现这个 timer。

## 标题和正文共用现有 gutter

collapsed 与 expanded 的标题都使用同宽的 `gutter(◆) + label`。
展开标题不再使用 `gutter(▎) + "◆ " + label`；正文的 `▎` 留在已有 gutter 中，不增加一层缩进。
标题预算、正文 wrap 和鼠标命中使用同一可用 cell 宽度，主 transcript 和侧面板都适用。
不新增容器或另一套 renderer；保持已有视口锚定，只消除额外横移，不保证展开前后高度相同。

## 实施落点与验收方法

相关所有者与验证落点：

- `crates/dim-cli/src/projection/thinking.rs`：客户端投影的有界增量选择，随 durable／preview 的既有边界派生显示文本。
- `crates/dim-cli/src/ui/tui.rs`：现有投影到 frame 的更新、逐块选择和事件循环；
  增加有界派生摘录及手势到期处理，不把工作放入业务 owner 或模型任务。
- `crates/dim-cli/src/ui/transcript/blocks.rs`：collapsed 消费已选片段；expanded 标题直接复用同宽 gutter，
  保留完整正文和现有 scrollback streaming 路径。
- `crates/dim-cli/src/ui/render/fullscreen.rs`：保留选择／链接优先级，提供思考正文命中与取消信号；
  到期折叠由具有真实块身份和展开选择的客户端处理，不让 renderer 猜业务身份。
- `crates/dim-cli/src/ui/text.rs`、`crates/dim-cli/src/sanitize.rs`：复用现有宽度和安全清理规则；
  仅在跨 delta 清理确有缺口时扩展原 owner，不再包一套清理器。
- owner 合同更新 `cli-commands.md` 的原文摘取／刷新规则及 CLI README 的正文手势约定；不更改 accepted ADR。

实现时优先扩展已有 TUI flow 和渲染场景，不为私有候选函数建立独立测试体系：

| 场景 | 可观察的验收结果 |
| --- | --- |
| 上述三段原文逐 delta 到来；英文句点跨 delta、小数、URL、硬换行、持续半句、长无换行文本 | 完整摘录保持稳定，新完成单元才替换；没有完整文本时不编造；长句有截断标记 |
| 无 visible reasoning、空白、中文、组合字符、ZWJ emoji、跨 delta 控制序列 | 无假摘要、无终端控制效果；行宽合法、grapheme 不被截断 |
| preview→durable、撤销 preview、结束、中断、resize、Session／分支切换 | 不串摘录、不重复正文、不丢手动选择；完成用时保持原合同 |
| scrollback collapsed／expanded，正文超过既有 preview 行数 | live 刷新不刷永久日志；expanded 所有正文恰好输出一次，无新增上限 |
| fullscreen 主区域及侧面板：标题、正文、gutter、内部空白、块外空白和相邻其他类型块 | 标题即时切换；正文只在窗口后收起一次；范围外不折叠 |
| 单击后继续双击／三击、拖动、链接、滚动条、滚动、resize、切换、块失效、先手动折叠再展开 | 选择和链接保持原效果；旧手势不对新块或重新展开的块生效；键盘操作不变 |
| tmux 100／60／40／32 列，含中文和 emoji；两种模式及侧面板 | 同宽下折叠／展开标题同列，正文 gutter 不挤占第二层宽度，复制与视口锚定不退化 |

使用本地 SSE fixture 和隔离 `--home`，在同一源码基线与修改版运行相同输入和工具脚本。
记录实际模型请求数、请求内容、用户输入、工具调用及终态；显示 timer 不得增加 RPC 或模型输入。
模型请求与工具终态对比必须来自执行记录，不能仅凭“纯 UI 代码”断言零影响。

性能验收固定可见宽度、delta 频率及增量大小，对比 64 KiB、1 MiB、8 MiB 的同类思考文本，
分别记录摘录选择耗时、总 frame 耗时、输入／Stop 到处理的 p50／p95／最大延迟，以及 RSS。
摘录的单次读取量不得随历史长度增长，不复制整块正文；固定尾部和变化频率时摘录成本应基本稳定。
总 frame 的既有全量成本需单列，不能用摘录计时掩盖；若输入延迟随长度增长，定位实际路径后再决定是否扩大修改范围。
实施前记录基线，实施后保存实际终端前后 capture 和检查过的截图，不能以本文件示意替代。

## Rule check 与消融审查

这是 CLI 显示与鼠标交互设计，不增加插件、part 或 Capability。
消费的公开输入仍是 [Clients](clients.md#timeline-block-identity) 约定的进度与历史投影，
不添加或修改任何 service face，不读取 ModelProvider 私有状态。

principles §1／§4 rules 1–3、5–6、9 的命令、交接、`before`、batch 和上下文写入不适用：没有业务事实或执行变化。
rules 4、7–8 保持基础机制与消费端边界，客户端只处理显示；ADR 002 D1–D5 不新增 scope、wiring、
业务配置或跨语言数据合同。界面关闭仅丢弃派生缓存和待确认手势，不终止后台执行。

不引入辅助模型、progress tool、新事件、持久化摘要、第二份全文、后台 timer 任务和新命令／开关。
必要结构只剩有界片段／绘制水位及一个待确认手势：前者保留可读摘录并合并 delta，
后者用于在不破坏双击选词的前提下确认正文单击。安全清理保留跨 delta 的解析状态。
增量单元选择消除了额外的尾窗缓存和周期扫描，不需要通用摘要容器。
不新增通用摘要框架或可配置策略层；布局直接删除多余标题前缀。

## Requirements raised to mechanism owners

无新增需求。沿用现有 progress、历史块身份、offset、设置、投影和终端事件循环；
不要求 App Server、ModelProvider、Timeline 或 rutis 提供新机制。
