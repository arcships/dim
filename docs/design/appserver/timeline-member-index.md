# Timeline：未完成成员索引

Status: Draft.
Scope: Store 对既有反关联查询的执行和持久索引。
Issue: [#1320](https://github.com/arcships/dim/issues/1320)。
合同：[属性查询](../timeline-property-query.md)、[原生存储格式](native-storage-format.md)。

## 1. 决定

调用方继续查询“开始事实不存在对应终态”。Store 为明确支持的等值反关联形状维护未完成成员，查询时定位成员集合，而不是从全部开始事实逐个排除。

不增加插件数据库接口、用户索引配置、运行时索引注册服务或 pending 专用查询方法。基础成员结构的格式决定见[原生格式 v37](native-storage-format.md#v37未完成集合索引的格式决定)。本文只处理未结束业务对象；owner各自的保存与恢复见[保存边界](../owner-state-indexed-reads.md)，不另建源确认成员树。

## 2. 索引描述

Store 的静态描述表记录：开始类型、终态类型、两端关联属性，以及终态本身的标量条件。它是通用等值反关联的执行描述，不运行插件代码，不解析 Goal 文本或 token。业务查询负责声明它需要什么条件。

初始覆盖范围：

| 开始 | 关联到终态 | 额外条件 |
| --- | --- | --- |
| input/message.id | consumed/deleted.input_id | v40维护handover缺失/存在两种互斥分组；公共pending只用缺失组，Queue恢复分别用两组。 |
| step/tool-call.id | step/tool-result.call_event_id | 工具名称是公开数组属性，作为成员分组键；不在 Store 写 ask_user 特例。 |
| exec/started.task_id | exec/ended.task_id | 无。 |
| collaboration/request.id | result.request_event_id 或 delivered.op_event_id | delivered 只有 error 关闭该成员。 |
| approval/request.approval_id | respond/cancelled.approval_id | v42；只读尚未答复的审批。 |
| collaboration 四种操作的 id | delivered.op_event_id | v42；只读尚未交付的操作，不恢复调用栈。 |
| exec/ended.id | input/message.tags 的固定前缀加 ID | v42；只有 completed/failed 且发生在有效代中的结果进入通知集合。 |

v42 的通知资格、任务身份保留和事务升级由[原生格式 v42](native-storage-format.md#v42-indexes-for-unfinished-external-work)唯一规定。查询用公开 concat/root 表达完整关系；不向调用方暴露成员类型名称。exec 的历史起点定位记录保留，终态仍从当前未结束根移除它。

索引描述必须与查询条件逐项等价；少一个终态、不同的关联字段或不同范围，不能套用近似结果。上述终态关联键是标量。复杂任意表达式仍沿用通用执行器，正常 owner inventory 只使用已验证支持的形状。

模型与压缩恢复的五种新增描述见[身份与恢复操作查询 §3](timeline-identity-reads.md#3-恢复操作的成员集合)，采用已确认的 v40；不改变四种原关联键；input增加的存在组见[状态字段索引](timeline-state-read-indexes.md)。

初始只加速单个分支段、从序号 1 开始、无 publishing tail 的公共 pending 查询。带 from 的裁剪会改变终态可见性，不能直接使用完整分支的成员根；多段 chain 也不能简单并集。两类范围保留原查询能力，不作为正常 pending 的隐藏替代路径。

## 3. 保存对象

| 对象 | 内容 |
| --- | --- |
| 成员 | 开始事件的原位置、终态关联键，以及工具名称等已声明的分组标量。位置定位原事实，不在树节点重复保存事件 ID 或正文。 |
| 集合版本 | 索引身份、Session、分支、截止序号、集合根。 |
| 不可变节点 | 按原位置排序的 AVL 节点；保存成员引用、左右子节点身份与高度。 |
| 终态键 | 已出现的关闭关系及最早位置，用于终态先出现、开始事实后出现的情况。 |
| 反向定位 | 从关联键找到本次要移除的成员和分组，不扫描所有集合成员。 |

选择按路径复制的有序树保存集合版本。旧 through 仍指向旧根；新增/移除只写本次受影响的路径。禁止每次更新序列化整个当前集合，也不使用每个历史 ID 分组取最后状态来查询集合。

首版采用 AVL 树，不引入叶块、内部块两种编码或节点缓存。节点高度受当前成员数约束；页读取从游标沿树路径定位。空集合使用 null 根，不为零成员查询访问旧 origin。每个已初始化分支、索引保留序号 0 的空根记录；缺少该记录是索引错误。

## 4. 原子写入

```text
存储接收原事实批次
  -> 按逻辑事件顺序取得关联属性
  -> 开始事实：没有关闭关系时加入成员
  -> 终态事实：登记关闭键并移除匹配成员
  -> 仅复制受影响树路径
  -> 同一 SQLite 事务保存原事实、节点和集合版本
  -> 提交成功后执行原发布回调
```

同批次的开始和终态可以留下历史需要的中间版本，但不单独提交。发布失败不保留索引更新；提交成功后崩溃，索引和事实同时存在。重复终态是幂等移除。不能只按原子批次末尾存一个版本，因为 query 的 through 可以指向已提交批次的内部位置。

物理输出行合并、Session 复制和删除沿逻辑身份维护索引；复制时按目标事实建立对应根；删除 Session 时同事务删除其根和关系。本轮不单独回收仍属于 Session 的旧版本节点；不在普通读取中做回收。

## 5. 读取

以下名称是私有 schema 的逻辑形状，不是插件可寻址的表：

```sql
SELECT root_id
FROM timeline_member_roots
WHERE session_id = ? AND branch_id = ? AND index_id = ? AND group_key = ?
  AND sequence <= ?
ORDER BY sequence DESC
LIMIT 1;
```

主键为 `(session_id, branch_id, index_id, group_key, sequence)`。取得根后按节点 ID 点查，从页游标的位置向后读 limit+1 个成员。当前根可达节点不含已移除的旧成员；旧根保留原成员。再按选中身份批量投影用户正文、问题参数、任务说明等真正需要的字段。

工具名称筛选定位对应分组根；同一 tool-call 含重复名称时，同一分组仅保留一个事件成员。每批问题的所有匹配 calls 仍保持原下标。

输入和工具索引不另存一份无分组集合。输入查询必须带 handover 缺失或存在条件。指定工具名称时定位该名称的根；ToolExecutor 查询全部未完成批次时，通过主键的 group_key > 上一名称逐个定位不同名称，再读取各名称在固定 through 的根，按原事件位置合并、去重、限量。不使用 DISTINCT 枚举所有历史版本，也不退回全部 tool-call 排除终态。名称枚举成本按历史上不同工具名称数 G 计；根和事件读取仍按当前成员计。每条分支的序号 0 空根只证明索引已初始化，不代表另一个待维护集合。

续页绑定索引描述版本、分组、原 through 和末尾成员位置；不绑定 SQLite 游标或进程内句柄。并发提交只生成新根，不改变旧页范围。

公共读取没有 publishing tail。内部查询若包含尚未落盘尾部，只对捕获的尾部变化建立临时节点；旧根不修改。该成本随未提交尾部变化增长，必须单独报告，不能算成已经消除的历史扫描。

## 6. 成本和边界

设当前成员为 K，一页返回 P 个成员：查询先定位一次版本，再访问树路径及本页节点，之后读 P 个对象的必要字段。增加已结束历史只增加版本定位的树高度，不允许增加 origin 或终态检查次数。

一次加入/移除写受影响路径，不是 K 条成员；删除一个有关联键的对象先做反向定位。批次内共享路径只保存最终所需节点。节点、版本、终态键和写放大都是实际新增开销，必须与减少的读成本一起测量。

已有普通 B-tree 的 `(from, to)` 区间表不替代本结构：仅写 `from <= S AND to > S` 并不能证明旧历史不被扫描。

## 7. 初始化、错误和验收

升级事务从历史一次建立索引，记录进度；失败时整体回滚，不能标记新格式成功。不能把未来才出现的结果用于改写旧 cutoff 的 pending 结果。已有正确索引的普通打开不重新建立。缺节点、根越界、定义版本不符是存储错误，不静默退回历史反关联。

一次性数据库验证：pending 固定 10，历史 6,000/60,000；零 pending；一页/多页；重复终态；终态先于开始；批次内部 through；并发续页；工具名称重复；Session 复制和删除；提交各阶段崩溃。累计节点查询、SQL VM、正文读取和 WAL，不只报告返回行数。

MemoryTimelineStore 维护相同的关系和集合版本语义。持久格式和复制后的引用验证归 Store，业务所有者继续决定何时产生开始与终态。

删减：不持久化查询结果正文、不增加业务状态机、不缓存完整历史。本轮固定使用现有版本 AVL，不重新选结构；它服务旧 through 和分页，与 Goal/队列本代的标准集合分开。正常 pending 不受已结束历史线性影响，是保留该机制的验收依据。
