# 上下文拼装与识别：业务需求与技术需求

状态：需求定义，不是设计。交付状态在 issue，不在本文。

Scope: branch。本文只定义一次模型步骤里“上下文拼装”和“上下文识别”必须满足的业务条件，以及为了满足这些条件允许采用的加速技术。实现方案见[上下文重建的内存计划](context-replay-memory.md)。

## 1. 两个概念

**上下文拼装**：调用模型前，从 Timeline 生成这一次请求的消息集合，包括顺序、压缩替换内容、固定保留输入、工具结果和摘要。

**上下文识别**：判断历史中哪些事件属于当前上下文、哪些已经被压缩替换、当前轮次采用了哪些输入、哪些工具结果进入摘要、哪个压缩切点合法。

拼装回答“发什么”，识别回答“为什么发这些、为什么不发那些”。

## 2. 业务需求

业务需求不因内存优化改变。

### 2.1 正确性

1. 在同一个历史位置、同一个已完成的压缩结果、同一轮对话下，拼装出的消息集合必须和完整重放完全一致。
2. 消息顺序必须一致。
3. 用户输入、工具调用和工具结果不能因为读取方式改变而丢失或换位。
4. 前缀校验发现不一致时，请求不能发出。

### 2.2 用户输入

1. 一轮对话采用的输入必须出现在该轮上下文里。
2. 输入可以在轮次开始前排队、轮次开始后才被采用；这种输入不能被漏掉。
3. 被压缩结果固定保留的用户输入必须保留正文，不能只保留编号。
4. 被压缩掉的输入不能重新出现在后续上下文里，除非它被明确保留或重新输入。

### 2.3 压缩

1. 只有最新一次“完成”的压缩生效。
2. 失败、跳过、未完成的压缩不能覆盖上一次完成结果。
3. 压缩切点必须满足保留范围、消息顺序和工具调用/结果配对。
4. 新压缩的摘要只能包含上一次切点之后的工具结果。
5. 压缩写入的快照是派生数据，不能替代真实历史。

### 2.4 分支

1. 子分支看到的祖先历史必须截止到分叉位置。
2. 祖先的配置、压缩结果、工具结果按祖先实际顺序参与，不能按子分支内序号重新排序。
3. 子分支自己的事件不能进入祖先或其他分支。
4. 跨分支的压缩切点和摘要顺序必须使用全局顺序，不能只比较分支内序号。

### 2.5 失败行为

1. 读取失败、解码失败、切点找不到、数据损坏时，不能生成缺失内容的请求。
2. 能证明完整读取结果时，可以回退完整读取。
3. 不能证明时，本轮失败并保留原上下文，不能静默继续。
4. 测量命令不能修改用户提供的数据库。

## 3. 加速技术需求

加速技术只解决“怎样少占内存、少做重复工作”，不改变第 2 节的业务结果。

### 3.1 内存

1. 一次准备步骤的峰值只跟当前批次和当前投影有关，不跟历史总长度成正比。
2. 不保留跨准备步骤的完整历史或完整事件集合。
3. 单个五十万 token 会话自身常驻不超过十兆；调用瞬间的服务商请求体/响应不超过二十五兆。
4. 进程常驻内存目标：单会话不超过五十兆，双会话不超过八十兆，空闲不超过三十兆。
5. 分配器回收只能作为兜底，不能代替结构修复。

### 3.2 读取

1. 事件正文按批读取，投影完成后立即释放。
2. 策略需要的固定事实、全局顺序、压缩所需事件分别查询，不构造完整历史。
3. 每步仍然读取全量事件；不承诺降低磁盘读取量或中央处理器时间。
4. 不引入需要失效规则的投影缓存。
5. 不在准备步骤之间保留派生位置。

### 3.3 一致性

1. 分批投影和完整投影必须使用同一套投影规则和状态推进方式。
2. 分批读取结果和完整读取结果在同一前缀上必须相同。
3. 无法证明一致时回退完整读取；回退不是错误，但必须可观察。
4. 默认内存存储和数据库存储的事实选择必须一致。
5. 新增策略相关事件时，两处选择规则必须同步；当前这是维护风险，需要由回归测试覆盖。

### 3.4 兼容

1. 不改变事件格式、持久化格式、协议或请求序列化。
2. 不改变压缩质量目标和策略选择规则。
3. 不新增模型上下文入口；事件仍只通过被采用的输入和工具结果进入上下文。
4. 不改变快照的持久化契约。

### 3.5 测量

1. 测量使用一次性数据库副本，包含一致的预写日志快照。
2. 报告必须区分实际存活分配和进程常驻内存。
3. 无法读取进程内存的平台返回不可用，不能返回零。
4. 测量结果只用于验收，不作为运行时行为。

## 4. 业务需求与技术需求的边界

| 问题 | 归属 |
| --- | --- |
| 模型这次应该看到哪些消息 | 业务需求 |
| 哪些输入被采用、哪些被压缩 | 业务需求 |
| 压缩切点是否合法 | 业务需求 |
| 按批读取还是一次读取 | 技术需求 |
| 用共享对象还是复制 | 技术需求 |
| 内存峰值和进程常驻目标 | 技术需求 |
| 读取失败时回退还是失败 | 业务需求决定结果，技术需求决定实现 |

发生冲突时，业务正确性优先于内存目标。

## 5. 验收

### 5.1 业务验收

- 同一前缀、同一压缩结果下，请求与完整重放一致。
- 轮次前排队、轮次内采用的输入不丢失。
- 只有最新完成压缩生效。
- 子分支按祖先顺序读取压缩和工具结果。
- 压缩切点非法、读取失败时不会发出缺内容的请求。

### 5.2 技术验收

- 上下文流程、存储流程、投影和工具绑定测试通过。
- 目标范围内的静态检查通过。
- 单会话、双会话、空闲进程内存按第 3.1 节测量。
- 测量命令不修改输入数据库。

### 5.3 当前结果

- 上下文流程九十五个测试通过。
- 存储流程五十二个测试通过，包含轮次前排队输入的回归。
- 投影与工具绑定十六个测试通过。
- 真实会话准备峰值从四十五点三九兆降到十一点五三兆。
- 单会话进程常驻约五十点八兆，双会话约五十四点六兆，空进程约二十九点七兆。
- 单会话比五十兆目标高零点八兆；恢复阶段仍有完整重放；真实服务商路径未复测。

## 6. 非目标

- 不减少模型步骤数。
- 不改变压缩算法和压缩质量。
- 不改变用户可见的上下文内容。
- 不通过缓存换取速度。
- 不通过分配器参数掩盖结构问题。
- 不把不同会话的投影合并复用。
