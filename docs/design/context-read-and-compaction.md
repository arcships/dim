## 1. 范围与非目标

范围：一条**与具体能力无关**的契约，回答三个问题：

1. 一个已提交事件如何声明它对模型上下文的贡献（消息）与它要跨断点保留的状态；
2. 一次读取从哪里开始收消息，之前的消息如何处理；
3. checkpoint 里放什么、规则是什么。

非目标（都归各自的文档或所有者，本文不描述、不规定）：

- 压缩策略保留什么、摘要怎么写、质量如何判断（[压缩需求](compaction-quality.md)）。
- 压缩的状态机、超时、退避、失败后果（[ContextCompaction](plugins/ContextCompaction.md)）。
- 某个能力如何组装自己的消息（助手消息、工具片段、中断输出、提示词折叠、输入采纳）。
- 提示词内容、`ModelRequest` 序列化、界面与协议。
- 准备步骤之间保留投影（[#710](https://github.com/arcships/dim/issues/710) 的方向）。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 贡献 | 事件自带的、对模型上下文的输入：一组消息片段，和/或若干键值状态 |
| 裁剪点 | 最近一次有效压缩所确定的边界位置；消息从这个位置之后开始收集 |
| 恢复位置 | 快照里状态重放的起点；不早于裁剪点（二者之间没有保留的消息条目） |
| checkpoint | 恢复位置 + 裁剪点 + 一张“键 → 值”表；表是恢复位置**之前**的状态；可丢的派生数据 |

位置一律用 `(段序号, 序号)` 表示：段序号按祖先链从根到当前分支递增。只写本地序号无法在祖先链上唯一定位。

## 3. 契约

### 3.1 贡献字段

每个已提交事件可以带两个可选字段，核心事件与插件事件完全一样：

| 字段 | 内容 | 约束 |
| --- | --- | --- |
| 消息 | 有序的消息片段：角色、内容、钉住标记 | 内容在提交时已确定；不在读取时再解释 |
| 状态 | 若干“键 → 完整值” | 一个事件可以同时写多个键；同批原子生效 |

规则：

1. **谁写事件谁填**。生产者负责贡献的内容与顺序；提交后读取方不再做领域解释。
2. **一个事件可以同时承担两种职责**：既可以贡献消息，也可以贡献状态；两者互不依赖。
3. **多键原子**：一个事件对多个键的修改一起生效，读取方不会看到只改了一半的状态。
4. **状态是完整值**，不是增量；怎么合并、怎么演进由写它的所有者决定。
5. **校验在提交边界**：形状、授权、大小在写入时校验；读取方不再逐层校验。

### 3.2 读取边界

一次读取先做三件事：

1. **找裁剪点**：最近一次有效压缩。没有压缩时，裁剪点是段的起点。
2. **定状态起点**：有快照时从快照的恢复位置重放状态，快照的表描述的就是恢复位置之前的状态；没有快照时从段首重放状态。状态重放可以早于裁剪点。
3. **收消息**：只从裁剪点之后收集消息；没有快照时从段首重放状态，但消息仍然只从裁剪点收集。裁剪点之前的消息**不进入收集**——不删除、不改写任何事件，只是不收集。

顺序与例外：

- 裁剪点的贡献（摘要、基线）排在收集结果的最前面，然后是裁剪点之后按序号收集的消息。这份贡献由压缩的所有者给出：它提供边界位置与对应的前缀贡献，机制只负责把它放在最前；所有者不得改写历史事件的字段，也不得让同一份前缀出现两次。
- 更早的裁剪点的贡献在裁剪点之前，因此不会被收集；两次压缩不会叠加过时的摘要。
- 没有快照时仍然从裁剪点收消息；从头重放只为重建状态，代价是读取量，不是消息量。
- 读取按物理行推进（`last_sequence`），被过滤的行不会让游标卡住或漏行。

### 3.3 checkpoint

checkpoint 有三样：

1. 恢复位置：状态重放的起点，`(段序号, 序号)`；
2. 裁剪点：消息收集的起点，`(段序号, 序号)`；
3. 一张表：**键 → 值**，值是完整 JSON，描述恢复位置**之前**的状态。

规则：

1. **同键取断点处最后一条**；断点之前的旧值在压缩后不再保留。
2. **键由所有者命名**，核心键用固定前缀，插件用自己的命名空间；换格式就换键名，不引入逐键版本字段。
3. **整份校验，不逐条丢**：快照有一个格式标记；标记不符或任一条读不出来，整份快照作废，回退重放。缺一个键可能让上下文失去立足点，所以不做“坏一条丢一条”。
4. **快照仍是可丢的派生数据**：不能用它替代事实；读不到就重放。
5. 旧的结构化快照直接作废，不迁移。

### 3.4 过滤

- 存储为“是否带贡献”维护一个派生标记，读取只取带标记的事件；`kind` 不参与上下文过滤。
- 标记只是索引，不参与语义；它的值完全由两个字段是否为空决定。

### 3.5 所有权

- 贡献是事实的一部分，写它的能力拥有它的含义；读取方只做“按序收集消息、按键覆盖状态”。
- 核心不解析别人的键值，也不替别人合并状态。
- 允许任何已提交事件贡献消息，是对现有“只有被采纳的输入和工具结果进入上下文”的规则变更；变更本身按 §5 提给规则的所有者，本文只定义机制。

## 4. 迁移与兼容

这是不兼容的持久化变化：事件增加两个可选字段、新增贡献标记、checkpoint 结构改变。

- 存储文档决定版本号与升级步骤；本文只要求：加列是即时的，填充是一次性的。
- **填充**：按会话跑一遍现有折叠，把每个事件的消息与状态写进新字段。
- **比对**：在该会话的每个裁剪点前缀、每条分支的固定祖先链上，比对“旧折叠的投影”和“字段重放的结果”；任何一处不一致，整个升级回滚。
- **暂存与发布**：每个会话的填充先写入暂存区，不进入运行时可读范围；全部会话比对通过后，一次性发布并推进格式标记。失败则丢弃暂存、保留旧格式可用。这样“不允许部分提交”与“崩溃后续跑”不冲突：续跑续的是暂存，不是已发布状态。
- **断点续跑**：迁移状态持久化；崩溃后从上次完成的会话继续，未完成的会话既不会被当成已迁移，也不会被新读取方当成空上下文。
- **没有双路径**：运行时只读字段；旧折叠只存在于迁移任务里，迁移完成后删除。
- 旧快照直接作废；冻结的事件 fixture 随格式决定一起更新，迁移前后各留一份对照。

## 5. 规则检查

本文定义的是机制，不定义任何能力的行为。

- **§4 rule 4**：满足。贡献随事实提交，可从 Timeline 重建；checkpoint 是可丢的派生数据。
- **§4 rule 5**：满足。贡献与事件同批提交，不新增批次。
- **§4 rule 9**：满足。快照不能替代事实。
- **§4 rule 6 / AGENTS 规则 10**：**需要修改**。现行规则是“事件只通过被采纳的输入和工具结果进入模型上下文”；本契约允许任何已提交事实贡献消息。按 §6 提给规则所有者，确认后更新对应文档，本文不自行改写规则。
- **ADR 002 D1–D5**：branch 作用域；不新增 wiring 模块、配置项或生命周期变化；接口语言中立。
- **ADR 006 D1/D9**：机制只陈述一次；不重述压缩、提示词、渲染的合同。

## 6. 向所有者提出的需求

- **规则所有者（principles §4 rule 6、AGENTS 规则 10、上下文拼装与识别 §3.2.3）**
  - 变更：允许任何已提交事实贡献消息，不再限定“只有被采纳的输入和工具结果”；上下文入口的校验从“必须被采纳”改为“贡献在提交边界校验”。
  - 保留：输入与工具结果的采纳语义不变；它们仍然按原规则工作，只是不再是唯一入口。
- **Runtime（TimelineStore / Timeline）**
  - 需求：按贡献标记与序号的分页读取、`last_sequence` 推进；以显式状态起点开始的批读入口。
- **Storage（原生存储）**
  - 需求：两个字段、贡献标记与索引、checkpoint 结构变化、§4 的迁移任务与比对；版本由该文档决定。

## 7. 验收

| 项 | 方式 |
| --- | --- |
| 一条规则 | 核心事件与插件事件产生同样的效果；插件新增键不需要改核心 |
| 多键原子 | 一个事件同时改多个键，读取方看不到中间态 |
| 裁剪边界 | 裁剪点之前的消息不进入收集；裁剪点自己的贡献在最前；两次压缩不叠加旧摘要 |
| 无快照 | 从段首重放状态下仍只从裁剪点收消息，结果与有快照时一致 |
| checkpoint | 恢复位置与裁剪点都能按段唯一定位；同键取最新；整份校验失败即回退；旧快照作废后能正常重放 |
| 暂存与发布 | 任一预处理或比对失败时，暂存被丢弃、旧格式仍可用；全部通过后格式标记一次性推进，运行时看不到中间状态 |
| 过滤 | 不带贡献的事件不读；带贡献的插件事件与核心事件等价 |
| 迁移 | 每个裁剪点前缀与祖先链都比对一致；任一处不一致整库回滚；崩溃后续跑；未迁移会话不被当成空上下文 |
| 读取量 | 命中快照时状态从恢复位置重放、消息只收裁剪点之后的贡献事件；`context-breakdown` 对照 |

不设 CI 字节阈值；数值写进实现 PR。

## 8. 删减检查

- 不新增事件种类；核心与插件共用同一套字段。
- checkpoint 从封闭结构缩成“裁剪点 + 键值表”，删掉类型化字段与逐键版本。
- 读取集合从按类型的表变成“是否带贡献”一个标记。
- 不描述压缩策略、状态机、消息组装；它们留在各自的文档。
