# 025: The plugin runtime baseline is rutis 0.23

Decision status: Proposed.

## Context

Dim embeds [rutis](https://github.com/arcships/rutis) as its plugin runtime. The host crates, the `xtask`
type generator, the bundled Node runtime, the repository's TypeScript plugins and the Python SDK all pin the
same release, currently 0.19.3.

rutis 0.23.0 was released on 2026-11-20. Its session protocol is **5**; a protocol-4 host, runtime or SDK is
refused at the handshake, so every end of one deployment must move together. Between 0.19 and 0.23 rutis also
changed behavior Dim relies on: unload order, declared services and runtime-row `inject` gating (0.20),
`Error::Value` and error texts (0.21), synchronous filters, `provide` after unload and listener withdrawal
(0.22), and cancel acknowledgement, the `awaited` signal and chunked frames (0.23).

Dim bundles its Node and Python runtimes, so it cannot mix rutis versions inside one installation. The 0.19.3
pins therefore cannot stay while any bundled end moves.

## Decision

### D1. Pin one rutis release on every surface

Dim pins **rutis 0.23.0** in the workspace (`rutis`, `rutis-loader`, `rutis-bridge`), in `xtask`'s
`rutis-types`, in the bundled Node runtime and its TypeScript plugins, in the npm peer dependency and in the
Python requirement. One installation upgrades all of them together. There is no dual-version mode, no
compatibility shim and no runtime fallback.

### D2. Adopt rutis's forms directly

Where 0.21 changed `rutis_bridge::session::Error::Value` from a tuple variant to a struct variant, Dim calls
`Error::value`. Where 0.20–0.22 tightened plugin behavior, the plugin or row is corrected at its owner; Dim
adds no wrapper that reconstructs the old behavior.

`UndeclaredPolicy` remains at its default `Publish`. It is a service-name policy, not an authentication or
sandbox boundary, and this upgrade does not adopt it.

### D3. Chunking is transport, not a payload target

A 0.23 session keeps the 16 MiB transport message limit and adds the `chunk` frame: a larger frame is split
into chunks of at most 8 MiB and reassembled before dispatch. `max_transfer` is the ceiling for one frame
(256 MiB by default, `RUTIS_MAX_TRANSFER` for a deployment), not a default payload size. Dim keeps the
default ceiling and does not fragment payloads itself. A sender over its ceiling fails that call; a receiver
whose ceiling is smaller ends the session, so both ends of a deployment must agree on the limit. Where a
Dim face published an admission limit that the runtime used to enforce before chunking, the face now enforces
it before the write; `pluginFiles` text `replace` admits a serialized record up to the 16 MiB frame and is the
first case in this upgrade.

### D4. Behavior changes belong to their owner

- A TypeScript or Python plugin declares every service it reads in `inject`, or in `optional` when it can run
  without it.
- A runtime row's `inject` gates the row. A name the catalog does not share does not gate a Node row, so the
  audit checks each row's names against the shared catalog rather than assuming the row started.
- Event filter predicates answer synchronously.
- A cleanup does not provide services, register another cleanup or wait for another cleanup.
- A callback handed over by another plugin or the host is awaited outside a synchronous call.
- Tests that asserted the old 16 MiB refusal now assert Dim's own `too_large` refusal after the frame has
  crossed the session.

### D5. One reviewable upgrade

The version bumps, the mechanical `Error::value` rewrite, the runtime and plugin updates, the test changes,
the generated artifacts and this ADR land in one pull request. The migration rationale stays in the linked
rutis guides; this ADR records only the decision and its consequences.

## Consequences

- Session protocol 5 only. An older peer is refused with `incompatible session: the far end speaks protocol 4,
  this side 5: upgrade the far end`; there is no mixed-version session.
- 83 `Error::Value` call sites in 27 files change to `Error::value`; 29 arguments contain `.into()`, and the
  string-literal ones lose it because `Error::value` takes `impl Into<String>`.
- Error texts are not a contract; codes are. Dim matches no rutis error text, and tests that assert a text are
  updated only where they describe a behavior Dim owns.
- Cancelled calls are acknowledged by the callee; queued writes and close semantics change; event order around
  a row ending or unloading changes. The upgrade verifies these flows rather than adding new mechanisms.
- `npm/branch-services.d.ts` changes: data objects become `type` aliases instead of `interface`s. The module
  graph snapshots are not part of this change; #1946 retired them.
- `Session::new` reads `RUTIS_MAX_TRANSFER` and fails host startup on an invalid value. Dim accepts that
  failure instead of adding a second validation path.
- The 0.19 upgrade document and other 0.19.3 records remain snapshots; this ADR does not rewrite them.

## Non-goals

- Go, Swift and Kotlin runtimes, dylib plugins, remote runtimes, `rutis-host` dial/listen rows and the Cordis
  host.
- rutis 1.0 stabilization, a new plugin API or a new `rutis.json` format.
- Adopting `UndeclaredPolicy` as a security boundary or redesigning instance-level composition.

## Supersession

This ADR follows [ADR 015](015-scopes-are-plugins.md) for the scope model and sets the runtime version
baseline; it does not change ADR 015's decisions. No accepted ADR is modified.
