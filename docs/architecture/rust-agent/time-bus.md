# 时间总线总纲

状态：草案（2026-10-01）

Timeline 是每个分支的时间总线：事件写上总线，总线分配序号，按序号依次驱动订阅它的状态机。持久化是总线的性质，不是它的本质。

本文只定原则。各能力的设计与[事件驱动约定](event-driven-flows.md)从这里推导。

## 1. 只认序号

先后只看总线分配的序号。执行快慢、完成先后、订阅顺序都不是语义上的顺序，判断不能依赖它们。

## 2. 事件是总线上带序号的事实

- 事件类型有统一的契约；写入方可以有多个，都必须满足契约。
- 谁可以写哪种事件由业务决定。事件对某个状态机意味着什么，由该状态机自己定义，不做全局分类。
- 事件的契约包括消费规则：哪些状态机必须消费它，消费后要达到什么效果；具体怎么做由各状态机自己决定。例如中断信号：凡是会产生在途工作的状态机都必须消费，并结束自己在途的工作，包括中断之后才到达、仍属于被中断工作的请求。
- 每份状态只有一个所有者，即写入它的状态机；其他状态机可以消费同样的事件，自建所需的视图。状态机的决定只依据自己消费到的事件，不读其他状态机的内存状态。
- 一项工作的终态由发起它的状态机写。
- 一项工作的开启与终态写在发起方的总线上，即使工作在别处执行。发起方需要消费结果时，成功也要有事实。

## 3. 总线只承载影响后续行为的结果

不是所有状态都上总线。状态机的内存状态必须能由“总线历史 + 重新读取外部状态”恢复到等价：面对同样的后续事件，做出同样的决定。只存在于某一时刻内存中、无法这样恢复的状态，不能影响决定。

该要求约束跨工作、跨代继续使用的业务状态，不要求重建已结算的在途 I/O 的局部控制状态。例如模型调用出错后的重试尝试次数、等待预算与凭据恢复标记，只属于当前模型调用；重载时结算原工作，不恢复尝试、不影响下一项工作。此处划定适用范围，不允许不可重建的内存状态跨工作决定业务行为。

## 4. 写入前的复核归各状态机

状态机先做决定、稍后才写入时，写入前由它自己复核。复核只涉及要写的内容，以及序号在它之前的状态变化。复核是状态机自己的责任，总线不参与。

复核依据自身已消费的事件状态，不用已提交但未消费的尾部代替消费。生产方尚未消费中断时仍可能写出迟到请求；请求的消费者按序处理，依据已消费的中断取消属于该 turn 的请求（第 2 条），不能只靠生产方复核。

## 5. 副作用不重放

副作用发生在总线之外，总线上只有结果。重放、重建与继承都不重新执行副作用。状态机的新一代从明确的序号位置接手；上一代在途的每项工作都必须有终态。能力重载与进程重启对新一代是同一件事，按同一方式接手。

## 6. 总线之外

读取其他总线（子分支、其他 Session）的时机，以及读到哪里算完成，属于业务状态机自己的设计，不由总线规定。
